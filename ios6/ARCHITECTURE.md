# 实现原理与技术选型

## 核心选择：独立 App 控制器，而非争用唯一前台

iOS6 的用户屏幕、焦点和键盘仍只有一套。cophone 不让两个操作者轮流点击这块屏，而是在指定第三方 App 内创建独立的 `SearchViewController`，不放入任何 UIWindow 或用户导航栈。后台调用真实 App 的 `searchForKeyword`，读取该控制器的 `searchEnd`、加载状态及可用简介。没有另写 B 站搜索 HTTP 客户端代替真实 App 操作；也没有把独立界面叫成第二个完整 iOS 桌面。

这样减少坐标漂移、键盘冲突与前台切换；代价是接入与真实 App 版本强相关。目前明确限定 oldbili 2.0.6。它是一条 App 语义操作路线，不是通用视觉点击路线；弹窗等未知状态停止并报错，不宣称能处理任意弹窗。

## 从自然语言到真实结果

1. 用户通过 cophone 输入任务，或长按 Home 主动录音。千问转写，DeepSeek 理解目标；含糊任务追问，执行前由用户确认。
2. 请求包含 UUID、在线会话与时间戳，写入 cophone 自己的私有/共享任务通道。mobile 用户运行的 launchd 服务执行，不需电脑维持。
3. 后台静默启动支持的 oldbili 并申请有时限的执行许可，最长135秒；不把 App 切到前台。
4. DeepSeek 获得真实结果、加载/弹窗状态、历史动作和 `allowedActions`，每轮决定 `search / read / finish / stop`。结果不足可换关键词；最多7次决策，单次格式错误可有限纠正。
5. 本地策略拒绝任意方法名、未知字段、伪造视频 ID、未读就完成、重复 read 等非法动作。模型不能直接调用 URL、shell、登录、购买或收藏。
6. `finish` 比较已读取的真实候选，后台写入系统备忘录，并通过独立读取同一笔记 UUID 的标题和正文确认。没有保存回读确认就不发送成功通知。

当前 `read` 读取搜索结果中真实可用的候选简介，**不是播放视频或打开完整视频详情页**。推荐依据只包括标题、UP主、时长、播放数与简介。无法确认的信息明确保留不确定性。

## 使用者与 Agent 的资源隔离

- 用户屏幕：用户继续在 Safari 等 App 滚动、打字；后台控制器不 makeKey，不挂入用户 UIWindow，不抢输入焦点。
- oldbili：只操作独立实例；用户把 oldbili 切到前台时停止后续操作，不修改正在看的页面。
- 生命周期：App在线会话、操作UUID、插件会话、30秒命令有效期、有限后台许可共同约束；强退cophone、锁屏/超时或未知状态时不盲目继续。
- SpringBoard：Home 插件仅处理主动手势；锁屏/通话/在线采样在异步线程，主线程只读取有过期时间的快照，避免同步向自身发送 SBS RPC。0.1.2语音故障版本不交付，采用已验收0.1.3。

## 实际执行画面链路

`真实 oldbili 搜索控制器 → UIView/CALayer renderInContext → 手机PNG → cophone Documents → USB AFC → Mac本地浏览器`。

采集在 oldbili 主线程，每秒约1帧，320×460；仅针对当前 Agent 独立视图，不截取用户前台窗口。搜索结果加载后使用 App 自己的 UITableView 渲染，读取候选时滚动独立表格到所选结果。没有生成模拟手机页面。每帧包含实际时间、命令ID、控制器名和任务ID，Mac只接收与当前任务匹配且未过期的帧。任务完成后保留最后一帧并标注时间。

这是低帧率的真实后台 UIView 观察，不是系统虚拟显示器、屏幕录制或完整后台桌面镜像。当前版本不把摘要/生图的云端计算伪装成可见 App 点击；演示“实际执行画面”以真实 oldbili 多步任务为主。是否满足面试方的画面定义，应展示真实实现和限制，不只展示进度文字。

摘要、配图和目视官还导出独立的 `execution-state.json`：只挑选实际选文、API返回正文、采集到的应用/网页/视频信息及回读验证字段，不读取或导出密钥配置。配图另导出实际收到的PNG，Mac核对任务ID和SHA256后预览。界面支持切换同时存在的任务，明确将这些内容标为“实际执行数据”，与oldbili真实UIView截图区分；旧结果不能匹配新任务，断连或过期不标实时。

## 发行凭据与记录清理

两种IPA都不内置API Key。发行版通过自身Info.plist的 `CophoneRequireManualAPI=true` 启用策略：使用者必须在设置页手动保存相应平台Key；所有AI入口及后台执行器校验此标记，旧导入文件不会直接启用。自用版保持对手机现有私有配置的兼容，不放入GitHub交付目录。设置提供移除Key入口。

清除记录由App确认后向后台发送命令；后台再次检查运行中的AI、语音、视频和目视官任务，通过固定自有文件清单清理请求/结果、语音及执行缓存并重置内存回顾状态。保留API配置、菜单/在线设置、系统备忘录和照片，避免后台重新发布刚清除的记录。

## 其他真实任务

- Safari选文→确认→手机千问生成图→AssetsLibrary保存→cophone相簿→独立像素/相簿成员回读。
- Safari选文→手机DeepSeek摘要（含适量背景并区分原文/补充）→主题标题Notes→回读。
- 目视官：用户主动启动后记录应用时段、可取得的Safari网页标题/摘录和oldbili视频元数据，按应用分段写Notes；回顾在本地整理，不默认上传整段使用轨迹。

## 取舍与范围

Objective-C/UIKit 便于适配iOS6及真实运行时接口；mobile launchd让任务与App可见界面分离；Substrate提供旧系统上的有限接入能力。现代非越狱iOS不提供这些能力，本工程不承诺可直接移植。系统Notes使用本机已核对的数据模型/API及独立读回，涉及版本依赖。HTTPS保留证书校验，不用信任所有证书绕过旧系统TLS。

通知跳转曾在BBAction层修改但实际点击仍启动cophone；0.1.2改为在实际SBUserAgent本地通知启动入口选择目标；0.1.3再把每条通知绑定到具体结果URL。Notes采用系统Spotlight分发与ZINTEGERID（不是Z_PK），照片使用资产UUID。用户已确认直接进入指定笔记正文与单张大图，均未闪过cophone。只处理本应用的已验证完成动作，其他通知保持原路径。结果保存的真实性不依赖通知是否直接跳转。
