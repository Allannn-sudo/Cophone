# AI辅助开发与审查过程

本工程使用Coding Agent生成和修改Objective-C、Python安装/检查脚本及说明文档；用户提供设备、授权操作并进行真实手机操作验收。可执行检查与用户目视结果分开记录，不把编译通过当成功。

## 如何约束AI生成的实现

- 先从真实oldbili/iOS6运行时接口及类型编码确认可用能力，再写固定适配层；不让模型返回任意selector或坐标序列。
- 让LLM基于每轮observation、allowedActions和历史决定下一步；本地检查拒绝伪造ID、未读取即完成、重复读取及未知字段。
- 桌面上前台App标识为空是合法状态，不能直接当锁屏；用独立锁屏状态判定，修复后实际桌面语音任务由用户验收。
- 系统通知路由改写BBAction后仍失败，真实横幅点击推翻了静态推断；继续追到实际SBUserAgent启动链路，候选在验收前不列为稳定功能。
- Home插件早期在SpringBoard主线程同步查询SBS存在死锁风险；移到异步采样，手势主线程只读有时效快照，故障版不交付。
- 实际执行画面必须来自真实UIView像素；不接受网页模拟手机、旧帧冒充实时或仅显示进度。Mac只读三个固定导出文件，任务ID和时间戳匹配才标实时。

## 如何审查与验证

执行有意义的策略、状态与保存回读检查；核对armv7/SHA1签名、DEB过滤范围与权限。对手机执行真实任务，查看系统Notes/相簿，再请用户确认未抢屏幕/键盘及UI正常。交付目录按明确路径复制并生成SHA256，不复制API Key、手机记录或读取出的系统二进制。

这些约束和失败记录可用于答辩讲解。不能声称已经实现任意第三方App操作、视频全文理解、收藏、通用弹窗处理或现代非越狱iOS部署。
